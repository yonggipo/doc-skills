# doc-skills

한국어 기술 문서가 문서화 규칙을 지키도록 돕는 Claude Code 플러그인입니다  
글을 쓰기 전에는 세션에 지침을 넣고, 문서를 저장한 뒤에는 규칙 위반을 검사해 알려 줍니다

## 필요한 이유

LLM이 쓴 한국어 문서에는 같은 종류의 문제가 반복해서 나타납니다

- **형태 문제**: 제목에 줄표를 쓰거나, 제목을 질문으로 쓰거나, 표 칸에 문장을 넣습니다
- **어휘 문제**: 통용되지 않는 영어와 약어를 풀어 쓰지 않거나, 뜻이 흐린 비유를 씁니다
- **성격 문제**: 다음 사람이 작업 전에 읽을 문서에 지난 작업의 경위를 적습니다

프롬프트로 넣은 지침은 항상 지켜지지는 않으므로, 이 플러그인은 지침을 넣는 일과 지침을 지켰는지 검사하는 일을 함께 맡습니다

## 설치

Claude Code에서 아래 두 명령을 입력합니다

```bash
/plugin marketplace add yonggipo/doc-skills
/plugin install doc-skills@doc-skills
```

훅이 `python3` 명령으로 검사 스크립트를 실행하므로, 실행 경로에서 찾는 `python3`이 3.9 이상이어야 합니다  
지침은 `SessionStart` 훅이 넣으므로, 새 세션을 시작하거나 `/clear`를 실행한 뒤부터 세션에 들어갑니다  
설치한 플러그인을 끄거나 지우려면 `/plugin` 메뉴에서 관리합니다

## 사용 방법

### `doc-check` 스킬

LLM 판단 항목까지 확인하려면 스킬을 직접 부릅니다

```
/doc-skills:doc-check 문서.md
```

### 스크립트 직접 실행

플러그인을 설치하지 않아도 명령줄에서 스크립트를 바로 실행할 수 있습니다  
의존성이 없어 파이썬 3.9 이상이면 실행되며, macOS 기본 파이썬 3.9.6과 3.14.6에서 같은 검사 결과가 나오는 것을 확인했습니다

```bash
python3 scripts/doccheck.py 문서.md
python3 scripts/doccheck.py docs/*.md --format json
python3 scripts/doccheck.py 문서.md --max-cell 40
python3 scripts/doccheck.py --list-rules
```

- **`--format`**: 출력 형식을 `text`(기본값)나 `json`으로 정합니다
- **`--max-cell`**: 표 칸 상한을 정하며 기본값은 30자입니다
- **`--disable`**: 끌 규칙 이름을 쉼표로 구분해 받으며 기본값은 빈 값입니다
- **`--fail-on`**: 종료 코드 1을 내는 심각도 기준을 정하며 기본값은 `error`입니다
- **`--list-rules`**: 규칙 이름과 설명을 출력합니다
- **`--fix-breaks`**: `soft-break`에 걸린 줄 끝에 공백 두 칸을 붙여 파일을 직접 고칩니다

### 검사 제외 주석

규칙 문서는 금지한 표현을 예로 들어야 하므로 스스로 규칙을 어기게 됩니다  
줄 끝에 `doccheck: off` 주석을 붙이면 그 줄을 검사하지 않으며, 이때 규칙 이름을 적어도 그 줄의 모든 규칙이 꺼집니다

```markdown
줄표(—)를 쓰지 않는다 <!-- doccheck: off -->
```

주석만 있는 줄을 두면 그 파일 전체에서 검사를 끄고, 규칙 이름을 적으면 그 규칙만 끕니다  
이 줄은 파일 어디에 있어도 파일 전체에 적용되지만, 읽는 사람이 찾기 쉽도록 첫머리에 둡니다

```markdown
<!-- doccheck: off em-dash,trailing-period -->
```

## 동작 방식

| 구성 요소 | 하는 일 | 실행 시점 |
|---|---|---|
| `SessionStart` 훅 | 글쓰기 지침을 세션에 넣음 | 세션 시작·이어하기·비우기·요약 |
| `PostToolUse` 훅 | 고친 `.md` 문서 검사 | 문서를 쓰거나 고친 직후 |
| `doc-check` 스킬 | 스크립트 검사와 LLM 판단 | 사용자가 부를 때 |

`SessionStart` 훅은 `prompts/write/`의 파일을 파일 이름 순서대로 이어 붙여 넣으며, `matcher` 값은 `startup|resume|clear|compact`입니다  
`PostToolUse` 훅은 `Write`·`Edit`·`MultiEdit`가 끝난 뒤에 실행되며, 위반을 알리기만 하고 문서를 직접 고치지는 않습니다  
두 훅의 제한 시간은 모두 10초이며, 218줄짜리 문서를 검사하는 데 1.6밀리초가 걸리므로 이 값은 훅이 멈췄을 때만 중단시킵니다

## 스크립트 규칙 검사와 LLM 판단

줄표, 표 칸 길이, 제목 형태처럼 형태로 판별할 수 있는 규칙은 `scripts/doccheck.py`가 검사합니다  
낱말이 무엇을 가리키는지, 문단이 읽는 사람의 할 일을 바꾸는지처럼 문맥을 읽어야 하는 규칙은 `prompts/`의 기준에 따라 LLM이 판단합니다  
두 결과를 섞으면 어느 쪽이 형태로 확인된 것인지 구분할 수 없으므로, `doc-check` 스킬은 두 결과를 나눠서 보고합니다

### 스크립트 규칙 검사 항목

| 규칙 | 검출 대상 | 심각도 |
|---|---|---|
| `em-dash` | 줄표 | error |
| `heading-not-noun` | 의문형·서술형 제목 | warning |
| `heading-bare-numeral` | 명사 없이 수사만 있는 제목 | warning |
| `table-cell-long` | 상한을 넘긴 표 칸 | warning |
| `paragraph-cram` | 상한을 넘긴 문단 | warning |
| `mechanical-parallel` | 한 문단 안의 열거 표시 둘 이상 | warning |
| `line-multi-sentence` | 한 줄 안의 문장 둘 이상 | warning |
| `soft-break` | 줄 끝 공백 두 칸 없는 줄바꿈 | warning |
| `trailing-period` | 종결어미 뒤 마침표 | suggestion |

코드 블록과 인라인 코드는 그대로 실행되거나 복사되는 부분이라 문체를 고치면 동작이 달라지므로, 스크립트가 검사하지 않습니다

`table-cell-long`은 인라인 코드와 링크 주소를 뺀 칸의 글자 수가 30자를 넘으면 검출하며, `**굵게**` 같은 표시 문자도 글자 수에 들어갑니다  
30자는 한 줄 구(句)가 들어갈 만한 길이로 정한 검출용 수치이고, 칸을 고칠지 판단하는 기준은 칸이 문장인지입니다

`paragraph-cram`은 줄이 네 개를 넘는 문단을 검출합니다  
한국어 기술 문서 6,387문단 가운데 98.2%가 4문장 이하였으므로, 상한을 넘는 1.8%만 검출되도록 정했습니다

`mechanical-parallel`은 「첫째」·「둘째」라는 표현 자체를 위반으로 보지 않습니다  
항목마다 문단을 따로 두거나 목록으로 나누면 검사를 통과합니다

`line-multi-sentence`는 마침표가 없는 문서에서도 「~니다」로 끝나는 문장을 검출합니다  
「~한다」로 끝나는 문장은 「~한다 해도」처럼 종결형 뒤에 말이 이어지는 경우가 있어서, 마침표가 있을 때만 검출합니다

`heading-bare-numeral`은 제목 끝에 홀로 선 수사만 검출하므로, 「다섯 가지 원칙」처럼 수사 뒤에 단위 명사가 오면 통과합니다

`heading-not-noun`은 「~나」·「~까」처럼 어미만으로 판별하기 어려운 제목을 「무엇」·「어디」·「언제」 같은 의문사가 함께 있을 때만 검출하며, 의문사 전체 목록은 `scripts/doccheck.py`에 있습니다

### LLM 판단 항목

- 통용되지 않는 영어와 약어를 풀어 썼는지
- 뜻이 흐린 추상명사, 평가어, 비유를 쓰지 않았는지
- 행위의 주체를 빼지 않았는지
- 제목이 절 본문에서 다루는 대상을 가리키는지
- 이 문단을 작업 전에 읽으면 무엇이 달라지는지
- 같은 사실이 두 곳에 있는지
- 설정값에 지금 값과 그 값을 고른 근거가 적혀 있는지

위 목록은 대표 항목이며, 판단 기준 전체는 `prompts/`에 있습니다  
`prompts/`는 글을 쓸 때 세션에 넣는 지침과 같은 파일입니다

### 심각도와 종료 코드

- **`error`**: 어느 문서에서든 고쳐야 하는 위반입니다
- **`warning`**: 규칙을 어겼을 가능성이 크지만 문서에 따라 예외를 둘 수 있는 위반이며, 예외로 두는 방법은 「검사 제외 주석」에 있습니다
- **`suggestion`**: 스크립트가 후보만 제시하는 경우이며, 무엇이 맞는지는 사용자가 읽고 정합니다

기본값으로 실행하면 `error`가 있을 때만 종료 코드 1이 나옵니다  
`--fail-on`에 `warning`이나 `suggestion`을 지정하면 그 심각도나 그보다 심각한 위반이 하나라도 있을 때 1이 나오고, `never`를 지정하면 위반이 있어도 0이 나옵니다  
파일이 없거나, 마크다운이 아니거나, UTF-8로 읽을 수 없거나, 모르는 규칙 이름을 `--disable`에 넘기면 종료 코드 2가 나옵니다

## 파일 구성

| 파일 | 담는 것 | 읽히는 시점 |
|---|---|---|
| `prompts/write/` | 글을 쓸 때 지킬 지침 | 세션 시작 때 자동으로 |
| `prompts/review/` | 다 쓴 뒤에 보는 기준 | 스킬을 부를 때 |
| `skills/doc-check/SKILL.md` | 검사 절차와 보고 형식 | 스킬을 부를 때 |
| `scripts/doccheck.py` | 검사 규칙 아홉 개 | 훅과 스킬이 부를 때 |

`write/`에는 문장을 쓰는 순간에 필요한 조항만 두어 세션마다 넣고, 문서의 성격이나 중복처럼 다 쓴 뒤에 보는 기준은 `review/`에 두어 스킬을 부를 때만 읽습니다  
조항을 더하거나 고칠 때는 합쇼체로 쓰고, 조항마다 규칙이 필요한 이유와 [고치기 전 → 고친 뒤] 예시 하나를 붙입니다

## fluent-korean과 함께 쓰기

`fluent-korean`은 출력 스타일로 들어가 문장의 어휘와 구조를 다듬고, 이 플러그인은 쓰인 문서의 제목·문장부호·표·문단 구조를 검사합니다  
출력 스타일은 한 번에 하나만 지정할 수 있지만, 이 플러그인은 출력 스타일이 아니라 스킬과 훅이므로 `fluent-korean`을 출력 스타일로 지정한 채 함께 쓸 수 있습니다  
`prompts/`의 어휘 조항도 `fluent-korean`처럼 실제로 통용되는 낱말을 고르게 합니다

**`fluent-korean`은 짧은 세션에서 `.md` 문서의 문장에도 적용됩니다**  
다른 지침 없이 문서 작성을 조건마다 5번씩 맡겼을 때, 기본 스타일은 5번 모두 제목에 줄표를 썼지만 `fluent-korean`은 한 번도 쓰지 않았고 종결어미로 끝난 목록 항목도 74%에서 94%로 늘었습니다  
긴 세션이나 이 플러그인의 지침과 함께 쓸 때는 확인하지 않았으므로, 문서 어휘는 `doc-check` 스킬로 따로 확인합니다  
`fluent-korean` 제작자는 답변 밖의 출력에도 적용하려면 지침 끝에 「한국어로 출력되는 모든 결과물에도 이 지침들을 적용합니다」를 붙이라고 안내합니다

아래 예시는 같은 글 한 대목에서 조건마다 어느 도구가 어떤 부분을 맡는지 보여 주며, 괄호 안 건수는 그 글에 스크립트 규칙 검사를 실행한 결과입니다

**아무것도 적용하지 않았을 때** (검출 3건)

```markdown
## 3. 왜 캐시를 껐나

캐시를 껐습니다. 응답이 오래된 값을 주는 문제가 있었기 때문입니다. TTL 을 60000 으로 두면 됩니다.
```

**`fluent-korean`만 적용했을 때** (검출 2건)

```markdown
## 3. 캐시를 비활성화한 이유

응답에서 오래된 값이 반환되는 문제가 있었기 때문에 캐시를 비활성화했습니다. TTL 값은 `60000`으로 설정하면 됩니다.
```

**남은 마침표와 한 줄 두 문장은 `trailing-period`·`line-multi-sentence`가 검출하고, 풀어 쓰지 않은 `TTL`은 LLM 판단이 지적합니다**

**`doc-skills`만 적용했을 때** (검출 0건)

```markdown
## 3. 캐시 비활성화 이유

응답이 오래된 값을 주는 문제가 있어서 캐시를 껐습니다  
캐시 유지 시간(TTL) 을 60000 으로 두면 됩니다
```

**「껐습니다」와 「오래된 값을 주는」 같은 어휘는 `fluent-korean`이 맡는 부분이라 그대로 남습니다**

**둘 다 적용하고 LLM 판단까지 반영했을 때** (검출 0건)

```markdown
## 3. 캐시 유지 시간

원본이 1분마다 갱신되므로 캐시 유지 시간(TTL)은 `60000`(60초)으로 설정합니다  
이보다 길게 설정하면 응답에서 오래된 값이 반환됩니다
```

**경위를 적던 문서가 지금 설정과 그 근거를 적는 문서로 바뀐 부분은 `prompts/review/`의 기준을 읽은 LLM 판단이 지적합니다**

뒤 두 예시는 첫 줄 끝에 공백 두 칸이 있어서 `soft-break`를 통과합니다  
줄 끝 공백은 화면에 보이지 않으므로 원문을 열어야 확인할 수 있습니다

## 유의점

- **훅은 형태 규칙만 검사합니다**: 어휘와 문서의 성격은 `doc-check` 스킬을 불러야 확인됩니다
- **LLM 판단은 다시 읽으면 달라질 수 있습니다**: 같은 문서를 다시 판단하게 하면 결과가 바뀔 수 있습니다
- **세션마다 컨텍스트를 조금 더 씁니다**: 세션을 시작할 때 `prompts/write/`의 지침 약 6,600자가 들어갑니다
- **형태만으로는 판별할 수 없는 규칙이 있습니다**: 제목이 절 본문의 대상을 가리키는지, 문단에 주제가 하나인지는 스크립트가 검출한 뒤에도 사람이나 LLM이 읽고 판단해야 합니다
