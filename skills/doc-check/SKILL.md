# 문서 검사

이 스킬은 문서를 다 쓴 뒤에 문서화 규칙을 지켰는지 확인하는 절차입니다  
스크립트 규칙 검사를 먼저 실행하고, 그다음 `prompts/`의 기준으로 LLM 판단을 한 뒤, 두 결과를 나눠서 보고합니다

> [!IMPORTANT]  
> **스크립트를 실행하기 전에 「괜찮다」고 답하지 않습니다**  
> 스크립트로 검사할 수 있는 항목을 눈으로 훑어 판단하면 줄 끝 공백이나 표 칸 길이처럼 눈에 잘 띄지 않는 위반을 놓칩니다

## 1. 스크립트 규칙 검사

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/doccheck.py" 문서.md
```

파일을 여러 개 지정할 수 있으며, 자주 쓰는 옵션은 다음과 같습니다

- `--format json`: 프로그램이 받아 쓰는 형식으로 출력합니다
- `--max-cell 40`: 표 칸 상한을 바꿉니다 (기본값 30자)
- `--disable trailing-period`: 지정한 규칙을 끕니다
- `--fail-on warning`: 경고가 있어도 종료 코드 1을 냅니다
- `--list-rules`: 규칙 이름과 설명을 출력합니다

`CLAUDE_PLUGIN_ROOT`가 비어 있으면 이 파일이 있는 폴더를 기준으로 `../../scripts/doccheck.py`를 실행합니다

**규칙 설명과 심각도 설명을 이 문서에 옮겨 적지 않습니다**  
규칙 목록은 `--list-rules`가 출력하고, 심각도의 뜻은 README가 정본입니다  
같은 규칙 표를 README와 이 문서에 두었을 때 한쪽만 고쳐져 규칙 설명 다섯 군데가 서로 달라졌고, `heading-not-noun` 하나를 한쪽에서는 「의문형」, 다른 쪽에서는 「물음형」으로 불렀습니다

코드 블록과 인라인 코드는 그대로 실행되거나 복사되는 부분이므로 스크립트가 검사하지 않습니다  
규칙을 어긴 예를 일부러 적어야 하는 줄에는 줄 끝에 `<!-- doccheck: off -->`를 붙이고, 파일 전체에서 특정 규칙을 끄려면 `<!-- doccheck: off em-dash,trailing-period -->`만 있는 줄을 둡니다

## 2. LLM 판단

스크립트는 형태만 봅니다  
이 단계에서는 낱말이 무엇을 가리키는지, 문단이 읽는 사람의 할 일을 바꾸는지처럼 형태가 같아도 문서마다 답이 달라지는 항목을 판단합니다

**판단 기준은 `prompts/`의 파일에 있으며, 이 문서에 옮겨 적지 않습니다**  
글을 쓸 때 세션에 넣는 지침과 검사할 때 쓰는 기준이 같은 파일이어야 한쪽만 고쳐져 내용이 달라지는 일이 생기지 않습니다

- **`prompts/write/`**: 적용 범위·어휘·문장·제목·문장부호·구조를 다루며, 세션을 시작할 때 훅이 넣습니다
- **`prompts/review/`**: 문서의 성격과 중복 판별을 다루며, 이 스킬을 부를 때만 읽습니다

```bash
ls "${CLAUDE_PLUGIN_ROOT}/prompts/write" "${CLAUDE_PLUGIN_ROOT}/prompts/review"
```

**검사할 때는 두 폴더의 파일을 모두 다시 엽니다**  
세션을 시작할 때 들어온 `write/` 지침은 대화가 길어지면 요약되어 조항의 이유와 예시가 빠졌을 수 있습니다  
파일을 읽을 때 조항을 목록으로 줄여 옮기지 않으며, 그 이유는 `prompts/write/00-scope.md`에 있습니다

**조항을 한 번에 모두 판단하지 않고 파일 하나씩 판단합니다**  
조항을 17개로 두었던 구성에서 결과를 한 번에 적게 했을 때는 보고가 400줄을 넘었고 한 번 실행하는 데 15분이 걸렸습니다  
같은 조항을 네 묶음으로 나눠 묶음마다 4~7개만 보게 했을 때는 묶음 하나가 2~4분에 끝났고, 서브에이전트로 동시에 실행하면 전체 시간도 한 번에 실행할 때와 비슷했습니다  
지금은 조항이 파일 8개에 나뉘어 있고 파일마다 2~7개이므로, 파일 하나를 한 묶음으로 삼습니다

## 3. 보고 형식

스크립트가 검출한 것과 LLM이 판단한 것을 **나눠서** 보고합니다  
두 결과를 섞으면 어느 쪽이 형태로 확인된 것인지 읽는 사람이 구분할 수 없습니다

```
스크립트가 검출한 것
  em-dash 3건 (12·40·58줄)
  heading-not-noun 2건 (7·26줄)

LLM이 판단한 것
  「3. 배포 기록」은 한 일의 목록이라 작업 전에 읽어도 달라지는 것이 없습니다 (review/10-doc-purpose.md 1번)
  「fixture 를 만든다」의 fixture 는 통용되지 않는 영어입니다 (write/10-vocabulary.md 4번)
```

**스크립트가 검사하지 않은 항목을 검사했다고 보고하지 않습니다**  
LLM이 판단한 결과는 다시 읽으면 달라질 수 있다는 점도 함께 알립니다

## 4. 수정 절차

> [!WARNING]  
> **사용자에게 묻지 않고 문서를 고치지 않습니다**  
> 찾은 위반을 먼저 보여 주고, 무엇을 고칠지는 사용자가 정합니다  
> `prompts/write/30-headings.md` 7번 조항처럼 제목을 줄이면 결론이 사라지는 경우가 있기 때문입니다

**검사와 수정을 한 번에 맡기지 않습니다**  
「고쳐서 전문을 내놔라」처럼 수정까지 함께 맡기면 문서를 다시 쓰는 데 주의가 쏠려 검사가 덜 꼼꼼해집니다  
같은 문서를 같은 조항으로 검사했을 때, 수정까지 맡기면 1건을 고쳤고 찾기만 맡기면 55건을 찾았습니다  
위반 목록을 먼저 내놓고, 사용자가 고칠 항목을 정한 뒤에 그 목록대로 고칩니다

**고친 뒤에는 다시 확인합니다**  
스크립트를 다시 실행해 검출 건수가 줄었는지 확인합니다  
조항은 읽은 직후에는 잘 지켜지다가 문서가 길어질수록 덜 지켜지므로, 수정을 모두 마친 뒤에 고친 부분에 해당하는 `prompts/` 파일 하나만 한 번 더 확인합니다

## 5. 이 스킬의 범위 밖

- **문서를 둘 위치**: 레포마다 다르므로 그 레포의 규칙을 따릅니다
- **커밋 메시지**: 이 스킬은 검사하지 않으며, 그 레포의 커밋 규칙을 따릅니다
- **코드 주석**: 이 스킬은 `.md` 문서만 검사합니다
